# leancjson

[cJSON](https://github.com/DaveGamble/cJSON) rewritten in Lean 4, compiled to C by the Lean
compiler, with its unit tests replaced by machine-checked theorems.

- **Parser** (`cJSON_Parse`, `cJSON_ParseWithOpts`), **printer** (`cJSON_Print`,
  `cJSON_PrintUnformatted`), **minifier** (`cJSON_Minify`), **comparison** (`cJSON_Compare`)
  and the **tree API** (get / add / detach / delete / insert / replace / duplicate).
- 110 specs, 0 `sorry`, no axioms beyond Lean's standard three, no `native_decide`, no Mathlib.
- Output is byte-for-byte what cJSON prints for all of cJSON's example files.

## What is proved

All of this is in [`CJson/Spec.lean`](CJson/Spec.lean); the build fails if any of it stops holding.

| Guarantee | Spec |
|---|---|
| Parsing the printed text of any well-formed document returns that document (formatted and compact) | `parse_print`, `parse_printUnformatted` |
| The printer's output passes the strict parser with nothing left over | `parseStrict_print` |
| Everything the parser returns is well-formed, so print → parse is stable on any parsed input | `parse_wf`, `parse_print_parse` |
| Nothing nested deeper than 1000 is returned; everything up to 1000 is accepted | `parse_nesting_limit`, `parse_nesting_limit_reached` |
| Numbers round-trip exactly | `number_roundtrip` |
| Any byte string round-trips through escaping | `string_roundtrip` |
| `\uXXXX` decoding is right for every 16-bit value; the UTF-8 encoder is right for every code point | `parse_hex4_lower/upper`, `utf8_correct` |
| Minifying formatted output gives exactly the compact output | `minify_print` |
| `cJSON_Compare` is symmetric, and reflexive on documents without duplicate keys | `compare_symm`, `compare_refl` |
| Insert/detach are inverse; replace changes one item only; object lookups see what was added/replaced | section 8 |

"Well-formed" (`JSON.WF`) means numbers are in canonical form and nesting is at most 1000 —
exactly the documents the parser can produce (`parse_wf`).

Every case of cJSON's `tests/*.c` that makes sense for a pure function is a kernel-checked
vector in `Spec.lean`; the files in `tests/inputs` are theorems in `SpecExamples.lean`.

## Differences from cJSON

Each row was checked by running upstream cJSON (commit `6d9f244`) and this program on the same input.

| Input | cJSON | leancjson |
|---|---|---|
| `[9007199254740993]` | `[9.00719925474099e+15]` | `[9007199254740993]` |
| `[0.1234567890123456789]` | `[0.12345678901234568]` | `[0.1234567890123456789]` |
| `[1e400]` | `[null]` | `[1e+400]` |
| `[01]`, `[1.]` | accepted as `[1]` | rejected (not RFC 8259 numbers) |
| `"a\u12G4b"` | `"a"` (bad hex reads as NUL, which cuts the string) | rejected |
| minify `[ "a\\" , 1 ]` | `["a\\" , 1 ]` (the string never ends, so whitespace stays) | `["a\\",1]` |

- **Numbers are exact decimals**, not `double`: `mant × 10^exp`. Nothing is rounded, and the
  text printed uses C's `%g` shapes (`0.123`, `1e-09`, `1.23e+129`). `-0` reads as `0`, as
  it prints in cJSON; there is no NaN/Infinity. Comparison is exact, not within an epsilon.
- **Pure API.** Operations return new values (`Option` on failure) instead of mutating;
  the NULL-pointer, allocator-hook, reference and use-after-free tests have no counterpart.
  `cJSON_Compare(a, a)` on the same pointer is always true in C; here two equal documents
  with duplicate keys compare unequal, as two separately parsed copies do in cJSON.
- Not ported: `cJSON_Utils` (JSON Pointer / Patch), `cJSON_Raw`, error positions
  (`cJSON_GetErrorPtr`), `cJSON_PrintPreallocated`.

## What is not proved

- The IO shell (`Main.lean`: reading files, writing stdout).
- The Lean compiler and the C toolchain: the theorems are about the Lean definitions, and
  the C in `c/` is what Lean generates from them.
- Performance. Text is a linked list of bytes and printing arrays recurses per element;
  it handles megabytes comfortably, but it is not cJSON-fast and very long arrays
  (millions of elements) can exhaust the stack.

## Layout

    CJson/Basic.lean      data model: Bytes, Num, JSON, WF
    CJson/Number.lean     parse_number / print_number
    CJson/Str.lean        parse_string / print_string, \u escapes, UTF-8
    CJson/Parse.lean      parse_value, arrays, objects, ParseWithOpts
    CJson/Print.lean      print_value, formatted and compact
    CJson/Minify.lean     cJSON_Minify
    CJson/Api.lean        tree API and cJSON_Compare
    CJson/Proofs/         supporting lemmas
    CJson/Spec.lean       the specification (read this)
    CJson/SpecExamples.lean  cJSON's example files as theorems (generated)
    CJson/Audit.lean      axiom audit of every spec (generated by ./audit.sh)
    Main.lean             command line tool
    c/                    C generated by Lean

## Build

    lake build                 # checks every proof and builds .lake/build/bin/cjson
    cjson print   file.json    # formatted
    cjson compact file.json    # compact
    cjson minify  file.json    # strip whitespace and comments
    cjson check   file.json    # exit status says whether it is valid JSON

Lean 4.36.0, no dependencies.
